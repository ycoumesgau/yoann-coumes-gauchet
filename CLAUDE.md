## 1. The product

Yoann Coumes-Gauchet's personal site, and a demonstration in itself: the content is managed in
Payload 4, and everything on the site can be done from Claude through an MCP server. The public
repository shows how it is built. Facts about Yoann come from his validated reference document,
never from memory: a claim it does not back is not published.

## 3. Structure

- `src/collections/`: collection configs only, PascalCase, one export named like the file.
- `src/globals/`, `src/blocks/`: globals and page blocks.
- `src/domain/`: access functions, enumerations, validators. Pure, unit-tested.
- `src/migrations/`: generated by `payload migrate:create`, committed with their JSON snapshot.
- `src/app/(frontend)/`: the public site. `src/app/(payload)/`: generated admin and API routes.
- `docs/adr/`, `docs/plans/site.md`, `docs/pitfalls.md`.

## 4. Rules

1. **Schema in English, content in two locales** (`en` default, `fr`). User-facing text lives in
   Payload, never hard-coded in a component. One exemption: each language's own name and code
   (`localeLabels`, the switch), which are not translated.
2. **Payload 4 stores `_status` per locale**: publishing English does not publish French, and a
   locale publishes only with its own required fields (`tests/db/pages-access.test.ts`). The
   public site reads with `fallbackLocale: false`: no English text under a French URL.
3. **Access**: every function starts from a refusal. The only anonymous reads are published,
   untrashed documents (`publishedOrAdmin`), untrashed media, and the `site` global. Versions
   are never public (`readVersions: adminOnly`, or Payload copies `read` onto them). Only a
   `users` account is an administrator. **`overrideAccess: true` is refused by lint** in `src/`;
   pass the caller (`user` or `req`) instead.
4. **Migrations**: `payload migrate` only, in CI and production (`push: false`). Never edit a
   migration once applied anywhere. CI replays the chain from an empty database.
5. **Content never arrives through a migration**: it is entered through the MCP server or `/admin`.
   A tool the work needs and the MCP server lacks is added to it, in its own PR (ADR-2 §1).
6. **Nothing is deleted outright**: content collections (`pages`, `projects`, `media`) use
   `trash`, and a trashed document is never public; the MCP server deletes for good only after
   Yoann's explicit confirmation (ADR-2).
7. **Secrets** live in Vercel only. `.env` is local and ignored. A token is never printed.
8. **Never invent a fact about Yoann**, a figure, or a product rule: ask, or write an ADR.

## 5. Method

- **Before pushing**: the pre-push hook runs memory check, format, lint, types and unit tests,
  and says what it does not cover. Fix a red; never bypass it (`--no-verify` is refused by a hook).
- **One batch, one draft PR**, using `.github/pull_request_template.md`. The PR cites the
  mutation that turned each new guard red. A visible change ships with screenshots at 1440 and
  390 px.
- **Hostile review**: run `.claude/agents/hostile-reviewer.md` before calling a PR ready; check
  each finding before fixing it; record rejected ones in a PR comment.
- **A guard is believed only after it was seen red.**
- **Questions come first**: anything that needs Yoann's decision is asked before the code it
  would shape.
- Where to write: a story → `docs/plans/site.md`; a measured trap → `docs/pitfalls.md`, plus a
  one-line rule here if it changes behaviour; a state → §0, replacing.
